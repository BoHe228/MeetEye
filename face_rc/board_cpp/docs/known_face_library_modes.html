已知人脸库：不开持久库 vs 开启持久库

这页说明实时人脸识别在两种模式下如何加载图片、如何绑定姓名、是否写回特征库，以及在 debug JSON 中应该看哪些字段。

共同输入 实时检测到的人脸 crop 经五点对齐后送入 AdaFace，得到 512 维特征。
共同绑定逻辑 先尝试连续 2 次实时命中已知姓名，再用动态 FaceID 内部样本投票兜底。
关键差异 不开持久库只读照片特征；开启持久库会读写同名 .npy 特征。

模式 A：只使用图片即时特征

适合验证固定照片库、对比不同来源照片的识别差异、避免运行过程污染人脸库。

1. 启动加载照片从 mytest/face_rec/face_photos 或板端 face_photos 读取已知人脸图片。
↓
2. 图片提取特征普通照片会检测/五点对齐；*_aligned.jpg 直接作为已对齐人脸 resize 提特征。
↓
3. 特征只保存在内存每次程序启动都会重新从图片提特征，不读取也不更新持久 .npy。
↓
快速绑定路径
连续 2 次实时命中top1 同名，score ≥ 0.55，margin ≥ 0.08。
输出姓名debug: known_bind_consecutive_selected
兜底绑定路径
动态 FaceID 样本投票例如 face1 内部已有多张样本，都与已知人脸库比对。
输出姓名debug: known_bind_selected 或 known_bind_keep_same_name
↓
不会写回人脸库debug: known_update_reason=disabled，known_update_updated=false。

推荐命令

服务器端广角

python mytest/main_GPU_face_rc_webui.py \
  --webui \
  --projection-mode wide-angle \
  --wide-model-path ./yolo_model/yolov8n-face.pt \
  --wide-yolo-imgsz 864 \
  --use-face-rec \
  --save-json \
  --json-output yolo_pose_output/wide_angle_face_debug.jsonl

服务器端鱼眼

python mytest/main_GPU_face_rc_webui.py \
  --webui \
  --projection-mode fisheye-panorama \
  --model-path ./yolo_model/yolov8n-face.engine \
  --yolo-imgsz 864 \
  --no-use-osnet \
  --use-face-rec \
  --face-rec-align-mode five-point \
  --known-face-dir mytest/face_rec/face_photos \
  --save-json \
  --json-output yolo_pose_output/fisheye_face_debug.jsonl

观察字段

  • 姓名绑定 name、known_matched、known_bind_reason
  • 相似度 known_bind_selected_score、known_bind_scores
  • 不写回 known_update_reason=disabled

模式 B：开启持久特征库

适合让同一个姓名逐步积累更贴近当前摄像头的主特征和姿态样本。需要谨慎使用，防止错误样本写回。

1. 启动加载照片和持久特征照片仍作为基础来源；同时读取同名 .npy 和 .json 元数据。
↓
服务器端路径
默认特征目录mytest/face_rec/face_photo_features
板端 C++ 路径
默认特征目录face_photos/face_photo_features_cpp
↓
2. 仍先完成姓名绑定连续 2 次实时命中或动态 FaceID 样本投票确认后，才能更新对应姓名。
↓
主特征更新
score ≥ 0.65在图片特征基础上做主特征 EMA，debug: primary_ema_updated。
姿态样本更新
score ≥ 0.60可追加多姿态样本；过于重复会跳过，避免库里全是相同角度。
↓
3. 只更新同名特征，不改照片例如识别为某个已知姓名，只更新同名 .npy，不会改原始照片，也不会写到其他姓名下。

推荐命令

服务器端广角

python mytest/main_GPU_face_rc_webui.py \
  --webui \
  --projection-mode wide-angle \
  --wide-model-path ./yolo_model/yolov8n-face.pt \
  --wide-yolo-imgsz 864 \
  --use-face-rec \
  --save-json \
  --known-face-feature-library \
  --json-output yolo_pose_output/wide_angle_face_library_debug.jsonl

服务器端鱼眼

python mytest/main_GPU_face_rc_webui.py \
  --webui \
  --projection-mode fisheye-panorama \
  --model-path ./yolo_model/yolov8n-face.engine \
  --yolo-imgsz 864 \
  --no-use-osnet \
  --use-face-rec \
  --face-rec-align-mode five-point \
  --known-face-dir mytest/face_rec/face_photos \
  --known-face-feature-library \
  --save-json \
  --json-output yolo_pose_output/fisheye_face_library_debug.jsonl

观察字段

  • 写回成功 known_update_updated=true
  • 主特征 known_update_reason=primary_ema_updated
  • 姿态样本 known_update_reason=pose_sample_updated
  • 跳过原因 low_similarity、known_match_below_threshold、known_match_ambiguous

两种模式对照

项目 不开 --known-face-feature-library 开启 --known-face-feature-library
启动加载 从照片目录提取本次内存特征。 加载照片，同时读取或维护持久 .npy 特征。
已对齐照片 *_aligned.jpg 直接 resize 提特征，不二次检测。 同左，并可作为该姓名的图片基础特征。
姓名绑定 连续 2 次实时命中优先；动态样本投票兜底。 同左，绑定成功后才允许考虑写回。
写回行为 完全不写回，debug 通常为 disabled。 满足阈值后更新同名 .npy，不改原始照片。
适用场景 调试、复现实验、比较不同采集来源照片、避免污染库。 长期运行、希望人脸库适应当前摄像头姿态和画质。
主要风险 每次启动重新提特征，不能积累当前场景特征。 如果错误绑定后写回，可能污染该姓名的持久特征。

建议使用原则

  • 做识别逻辑调试时，先不开持久库，确认 name 和 known_bind_reason 符合预期。
  • 确认不会误认后，再打开 --known-face-feature-library 积累主特征和姿态样本。
  • 鱼眼场景建议使用鱼眼链路采集的 *_aligned.jpg 作为独立参考，文件名仍按现场姓名或代号命名。
  • 如果只是比较不同来源照片的差异，不要开启持久库，避免实时样本改变对比基准。
